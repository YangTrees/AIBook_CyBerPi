> **状态**：🟡 待开发（样板课之首）

## 📌 一、基础信息

| 项目 | 内容 |
|---|---|
| **课程名称** | 点点醒了 |
| **课时** | 60 分钟 |
| **分组** | 2 人一组，每组 1 台 CyberPi + 1 台电脑 |
| **编程目标** | mBlock 界面（设备区/积木区/脚本区）；**设备事件**；顺序执行；**上传按钮与两种模式** |
| **AI目标** | 输入 → 处理 → 输出；**程序上传后离开电脑也能工作** |
| **呼应原课** | 原第 1 课《小侦探找线索》（信息）、原第 31 课《超级搭档》（人机协作） |
| **上传验收** | **拔线、关掉 mBlock，按 B 键，点点仍然要打招呼** |

## 📜 二、剧情

云朵形的点点躺在桌上，屏幕黑着。团团怎么拍它都没反应——因为**点点的身体里还没有程序**。

> 团团："点点，你怎么不说话呀？"
> 点点：（屏幕全黑）
> 团团："原来是这样……点点需要我们用 mBlock 写一段程序，然后**上传**进它的身体里！"

**本课任务**：给点点写入第一段程序，让它能打招呼、说再见，并且**拔掉线也记得**。

## 🎯 三、知识点落点

课后孩子应能说出三句话：

1. "点点要收到一个**输入**（我按键），才会做**输出**（说话、亮灯、出声）。"
2. "程序**上传**以后就住在点点身体里了，拔掉线也还在。"
3. "在点点身上，要用'**当点点启动**'和'**当按键被按下**'，不能用绿旗和键盘。"

## 📱 五、程序规格

### 变量

本课不使用变量（保持首课极简）。

### 脚本 1 · 开机（当 CyberPi 启动）

```
清空屏幕
在第1行显示 "点点：）"
在第2行显示 "按B打招呼"
在第3行显示 "按A说再见"
设置全部灯为 青蓝(0,180,220)，亮度 20%
```

### 脚本 2 · 打招呼（当 B 键被按下）

```
清空屏幕
在第1行显示 "你好呀！"
在第2行显示 "我是点点"
设置全部灯为 橙色(255,140,40)
播放 音效【叮咚】
等待 1 秒
设置全部灯为 青蓝，亮度 20%
```

### 脚本 3 · 说再见（当 A 键被按下）

```
清空屏幕
在第1行显示 "再见~"
在第2行显示 "明天见"
设置全部灯为 紫色(160,80,220)
播放 音效【嘟】
等待 1 秒
设置全部灯为 青蓝，亮度 20%
```

### 起始版留空设计

起始版 `.mblock` 中，**脚本 3 的输出部分留空**（只保留事件头和"清空屏幕"），让孩子补 3 块积木：
① 第 1 行文字 ② 灯光颜色 ③ 音效。

## 🎮 六、课堂流程（60 分钟）

### 1. 故事警报（5 分钟）

播放原第 1 课《小侦探找线索》片段（30–60 秒），停在"点点没反应"处。

> 教师："点点为什么不动？它缺了什么？"

不急着给答案，收集孩子的猜想。

### 2. 无屏预测（10 分钟）· 机器人模仿游戏

**不碰电脑。** 两人一组，一人当"机器人"，一人当"程序员"。

- 程序员只能用三种指令：**拍左肩**（亮灯）、**拍右肩**（说话）、**拍头顶**（出声）
- 机器人必须严格照做，不能自己加戏
- 互换角色

复盘提问：

> "机器人什么时候不知道该做什么？" → 指令不清楚 / 没给指令
> "机器人的动作是从哪来的？" → 全部来自输入的指令

**建立术语**：输入 → 处理 → 输出。教师把这六个字写在白板上，整节课反复用。

### 3. 积木解密（10 分钟）· 制造认知冲突

**这一步是本课的核心教学事件，不要跳过。**

1. 教师演示 mBlock 界面：设备区、积木区、脚本区、右上角**模式开关（实时 / 上传）**、**上传按钮**。
2. 教师**故意**用【当绿旗被点击】写一个打招呼程序，连接设备，**上传**。
3. 上传完成，设备重启——**屏幕空白，按什么都没反应**。
4. 教师："咦？程序上传了，为什么点点没反应？"

让孩子猜 30 秒，不公布答案。

5. 教师切换到**实时模式**，点绿旗——**程序正常了**。
6. 引出结论，写在白板上：

| | 实时模式 | 上传模式 |
|---|---|---|
| 程序跑在哪 | 电脑 | 点点身体里 |
| 要不要连线 | 必须连 | **可以拔线** |
| 用什么事件 | 绿旗、键盘 | **当点点启动 / 当按键被按下** |

> 教师话术："绿旗是电脑上的旗子，点点看不见。点点只认得自己的开机和自己的按键。"

### 4. 程序搭建（15 分钟）

孩子打开起始版，补全脚本 3（说再见），并自行添加开机脚本。

教师巡回，重点检查：**有没有人又用了绿旗。**（一定会有）

### 5. 实时调试（8 分钟）

保持连接，实时模式下按 A / B 键，确认三种反应都正常。

**本课第一个测试**：连按 B 键 5 次，看会不会卡住或叠加错乱。

### 6. 上传实战（8 分钟）· 本课定义性动作

1. 切换到**上传模式**，点击**上传**
2. 等待进度条走完，设备自动重启
3. **拔掉 USB 线**
4. **关掉电脑上的 mBlock**
5. 按 B 键——点点仍然打招呼

> 教师话术："现在点点身体里有程序了。就算把电脑关掉，它也记得你。"

这一步要让孩子**亲手拔线**，不要由教师代劳。拔线后的反应是整门课程最重要的一次体验。

### 7. 复盘记录（4 分钟）

填写 AI 训练日志第 1 页（本课前 3 项），并回答：

> "如果点点没有收到按键，它会做什么？" → 什么都不做。**没有输入就没有输出。**

## 🧪 七、测试用例

| 类型 | 输入 | 预期结果 |
|---|---|---|
| 正常 | 按 B 键 1 次 | 屏幕"你好呀！"+ 橙灯 + 叮咚声 |
| 正常 | 按 A 键 1 次 | 屏幕"再见~" + 紫灯 + 嘟声 |
| 边界 | **连按 B 键 5 次** | 每次都完整播放，不卡死、不叠加错乱 |
| 边界 | 开机后不按任何键 | 停在待机画面，青蓝呼吸灯 |
| 意外 | **拔线 + 关掉 mBlock 后按 B** | **仍然打招呼**（本课核心验收） |
| 意外 | 用绿旗写的程序上传后按 B | 无反应（认知冲突实验） |

## ⭐ 八、三级任务卡

### 星芽级（6–8 岁）

- 教师提供起始版，脚本 3 缺 3 块积木；

### 星跃级（9–10 岁）

- 独立完成三个脚本（开机 / B / A），不加变量；

### 星航级（11–12 岁）

- 改成"**摇杆四方向四种反应**"：上/下/左/右各一种灯色 + 一句话；

- 额外挑战：**先用绿旗写一遍，上传，确认它失效**，再改回设备事件；
- **要说出来**：为什么绿旗在上传模式不能用？实时模式和上传模式该怎么选？

## ⚠️ 十、教师实施说明

### 常见故障

| 症状 | 原因 | 处理 |
|---|---|---|
| 上传后屏幕全黑，按什么都没反应 | 用了绿旗或键盘事件 | 改为【当 CyberPi 启动】/【当按键被按下】 |
| 上传按钮灰色点不了 | 未切到上传模式，或设备未连接 | 检查模式开关与连接状态 |
| 找不到端口 / 上传失败 | 数据线、USB 口、驱动、mLink | 换线换口；Web 版确认 mLink 已启动 |
| 连不上第二台设备 | 一次只能连一台 | 分组轮流上传 |
| 教学全程正常，回家作业打不开 | 学生只保存了设备程序，没存 `.mblock` | 强调每课结束另存 `.mblock` 到作品集 |

### 儿童误概念（及纠正话术）

1. **"程序存在电脑里"**
   → 拔线实验。话术："线拔了，电脑还连着点点吗？那它怎么还记得打招呼？"
2. **"绿旗在哪都能用"**
   → 认知冲突实验。话术："绿旗是插在电脑舞台上的，点点看不见它。"
3. **"上传等于保存"**
   → 上传会把程序放进设备**并覆盖掉上一个**。话术："点点身体里只能放一个程序，新的会把旧的挤出去，所以要留好 `L01` 文件。"
4. **"点点自己会想"**
   → 首课就要压住。话术："点点刚才做的每一件事，都是我们一条一条写进去的。它自己没有多加一个动作。"

# 第 2 课 · 开关城的两兄弟

> **状态**：🟡 待开发
> **呼应原课**：原第 2 课《开关城的两兄弟》（0 和 1）

## 📌 一、基础信息

| 项目 | 内容 |
|---|---|
| **课程名称** | 开关城的两兄弟 |
| **课时** | 65 分钟 |
| **编程目标** | 变量、列表、`如果/否则`、**列表索引读写**、循环求和 |
| **AI目标** | 0 和 1 是两种状态；**多个状态组合能表示更多信息** |
| **复用原课资产** | 黑白翻转卡 4 张（开开黄=1 / 关关蓝=0）、开关城地图 6 任务 |
| **上传验收** | 拔线后用摇杆 + A/B 键输入任意 5 位序列，5 颗灯亮灭正确、屏幕数值正确 |

## 📜 二、剧情

开关城的两兄弟——**开开**（黄，1）和**关关**（蓝，0）——在点点的 5 颗灯上安了家。

> 开开："我亮着的时候，就是 1！"
> 关关："我灭着的时候，就是 0。我也是信息！"
> 团团："关关，你什么都没做，也算信息吗？"
> 关关："当然算！不然你怎么知道这里是'灭'？"

**本课任务**：用摇杆和 A/B 键，在点点的 5 颗灯上摆出任意开关组合，并让点点算出这是数字几。

## 🎯 三、知识点落点

1. "**0 不是'没有'**，0 是一个状态，也是一种信息。"
2. "5 个开关能摆出 **32 种**组合，所以点点能用 5 颗灯表示 32 个数字。"
3. "同样的开关，**排列顺序不同，意思就不同**（10110 和 01101 不一样）。"

## 🧱 四、新积木清单

| 积木 | 功能 | 运行域 |
|---|---|---|
| 【新建列表 开关状态】 | 存 5 位 0/1 | 域 B ✅ |
| 【把 第 N 项 替换为 值】 | 改某一位 | 域 B ✅ |
| 【第 N 项 of 列表】 | 读某一位 | 域 B ✅ |
| 【如果…那么…否则】 | 分支 | 域 B ✅ |
| 【重复 N 次】/【重复执行直到】 | 循环 | 域 B ✅ |
| 【变量 数值 改变 / 设为】 | 累加换算 | 域 B ✅ |

## 📱 五、程序规格

### 变量与列表

```
列表 开关状态 = [0, 0, 0, 0, 0]     // 5 位，从左到右对应第 1–5 颗灯
列表 权值     = [16, 8, 4, 2, 1]
变量 当前位   = 0                    // 0–4，光标
变量 数值     = 0
变量 i        = 0                    // 循环计数
```

### 交互约定

| 操作 | 作用 |
|---|---|
| 摇杆 **左 / 右** | 光标左移 / 右移（到边界停住，不循环） |
| 按键 **A** | 当前位设为 **1**（灯亮橙） |
| 按键 **B** | 当前位设为 **0**（灯灭） |

### 脚本 1 · 开机

```
清空屏幕
把 当前位 设为 0
把 开关状态 全部设为 0
广播【刷新显示】
```

### 脚本 2 · 光标右移（当摇杆推向 右）

```
如果 当前位 < 4 那么
    当前位 增加 1
广播【刷新显示】
```

> ⚠️ **必须写边界判断**。不加判断时光标会跑到 5、6，读列表会出错——这是本课最重要的边界测试。

### 脚本 3 · 置 1（当 A 键被按下）

```
把 开关状态 的第 (当前位 + 1) 项 替换为 1
广播【刷新显示】
```

> 列表项号从 1 开始，光标从 0 开始，**+1 是必写的**。这是本课高频 Bug。

### 脚本 4 · 置 0（当 B 键被按下）

```
把 开关状态 的第 (当前位 + 1) 项 替换为 0
广播【刷新显示】
```

### 脚本 5 · 自定义积木【刷新显示】

```
// 1. 刷新 5 颗灯
重复 5 次（i 从 0 到 4）
    如果 开关状态 第 (i+1) 项 = 1 那么
        设置第 (i+1) 颗灯为 橙色(255,140,40)
    否则
        设置第 (i+1) 颗灯为 熄灭

// 2. 光标指示：把当前位的灯改成闪烁的青蓝（或加亮）
设置第 (当前位+1) 颗灯为 青蓝(0,180,220)   // 光标位用青蓝区分

// 3. 换算数值
把 数值 设为 0
重复 5 次（i 从 0 到 4）
    数值 = 数值 + (开关状态 第 (i+1) 项 × 权值 第 (i+1) 项)

// 4. 屏幕三行
在第1行显示 "开关城  位:(当前位+1)/5"
在第2行显示 (拼接 开关状态 为 "1 0 1 1 0" 形式)
在第3行显示 "= " + 数值
```

### 常见故障

| 症状 | 原因 | 处理 |
|---|---|---|
| 光标跑到第 6 位，屏幕显示奇怪数字 | 缺边界判断 | 补 `如果 当前位 < 4` |

| 摇杆事件不触发 | 用了键盘方向键事件 | 改为【当摇杆推向…】 |

### 儿童误概念

1. **"0 就是没有，不用管它"**
   → 关键纠正。话术："如果关关不存在，你就只能写 11111，摆不出 10110。0 是**一个位置上的一种状态**。"
2. **"10110 和 01101 一样（都是三个 1）"**
   → 让两组孩子各摆一个，对比数值（22 vs 13）。话术：**顺序也是信息**。
3. **"位数越多越好"**
   → 追问："那我们要不要给点点装 100 颗灯？" 引导到"位越多，占的地方也越多"——为第 7 课压缩埋线（V4 第 7 课）。

小邮差的信总是被偷看。团团和点点决定用**灯光的颜色和数量**写密码信——这样只有拿着同一本密码本的人，才看得懂。

## 🎯 三、知识点落点

1. "**编码**是给消息穿外套，**解码**是脱外套——两件都要用**同一本密码本**。"
2. "密码本不一样，解出来的意思就不一样——**编码不是保密，规则才是关键**。"
3. "颜色表示**类别**，亮几颗表示**序号**——这就是一套规则。"

- **要说出来**：编码和解码分别用了哪一段积木？如果密码本不一样会怎样？

### 星航级（11–12 岁）

- **自建密码本**：自己定义 1 个新词（如"回家"）及其颜色+数量，加入列表；
- 处理"**5 颗灯不够用**"的问题：动作类已有 5 个，如何给第 6 个动作编码？（引导：需要第 6 颗灯或一个第二位）
- 完成错版密码本测试，并写出结论；
- **要说出来**：编码和加密是一回事吗？如果我想让**只有一个人**看懂，光有密码本够不够？

## ⚠️ 十一、教师实施说明

### 常见故障

| 症状 | 原因 | 处理 |
|---|---|---|
| 亮的数量总是不对 | 内层循环次数取错了列表（用了"当前选择"而非"数量"） | 检查查表索引 |
| 空消息时灯乱闪或卡住 | 缺边界判断 | 补 `如果 项目数 = 0` |
| 三个词连在一起分不清 | 组间没有"熄灭 + 间隔" | 每组后加【熄灭全部灯】+【等待 0.3 秒】 |
| 屏幕显示的是数字不是词 | 显示的是索引而非 `密码本` 第 N 项 | 检查查表 |
| 摇杆选择不更新屏幕 | 忘记在选择脚本里刷新第 2 行 | 补显示积木 |

### 儿童误概念

1. **"密码就是保密"**
   → 错版密码本实验。话术："点点没骗人，灯也闪得一模一样。**编码只是换了个写法，不是加了锁。**想保密还得另想办法——我们第 29 课会讲。"
2. **"颜色越漂亮越好"**
   → 追问："如果红色表示'动作'，蓝色表示'角色'，我发红 1 颗，你还解得出'团团'吗？" 引导：**规则要对上，好不好看不重要。**
3. **"解码不用密码本，猜就行"**
   → 背对背测试会自然暴露：单词能猜，三词组合基本猜不对。

### 关键提问

- "蓝色亮 3 颗是什么意思？你是怎么知道的？"
- "如果密码本丢了，这串灯还能解开吗？"
- "点点发错了，还是我们看错了？"
- "光有密码本，能保证只有一个人看懂吗？"

# 第 4 课 ·【项目】点点数字名片

> **状态**：🟡 待开发（单元项目课）
> **呼应原课**：原 1（信息）、2（0和1）、3（编码）、6（RGB）

## 📌 一、基础信息

| 项目 | 内容 |
|---|---|
| **课程名称** | 点点数字名片 |
| **课时** | 75 分钟 |
| **编程目标** | **自定义积木（带参数）**、组合逻辑、多段协作 |
| **AI目标** | 综合——信息的**表示**（编码）、**存储**（变量与列表）、**传递**（共享规则） |
| **上传验收** | 拔线后按 B 键完整展示名片；**同学只看灯光能解码出名字** |
| **展示方式** | 名片交换会：设备传给同学，同学按 B 看名片并解码 |

## 📜 二、剧情

数字岛要办一场**名片交换会**。每个孩子都要给点点做一张名片，让陌生人也知道：你是谁、你最喜欢什么颜色、你会怎么打招呼。

> 点点："可是我的屏幕只有这么小……"
> 团团："那就用我们学过的办法——**用密码表示你的名字，用 RGB 表示你的颜色，用灯光动画表示你的问候**！"

## 🎯 三、知识点落点

1. "我的名字、颜色、问候，全都变成了**数字和规则**——这就是把信息'表示'出来。"
2. "名片上的信息存在**变量和列表**里，这叫**存储**。"
3. "别人要能看懂我的名片，得先知道**同一套规则**——这叫**共享的编码**。"

## 🧱 四、新积木清单

| 积木 | 功能 | 运行域 |
|---|---|---|
| 【新建积木 制作名片 (密码)(红)(绿)(蓝)(动画)】 | **带参数的自定义积木** | 域 B ✅ |
| 【调用 制作名片 …】 | 在事件里调用 | 域 B ✅ |
| 【设置第 N 颗灯为 RGB(r,g,b)】 | 用变量控制灯色 | 域 B ✅ |
| 【重复 N 次】嵌套 | 灯光动画 | 域 B ✅ |

## 📱 五、程序规格

### 名片内容（三项）

| 项 | 编码方式 | 来源课 |
|---|---|---|
| **名字** | 3 个词的密码（复用第 3 课密码本索引） | 第 3 课 |
| **代表色** | RGB 三通道数值 0–255 | 原第 6 课 |
| **问候动作** | 灯光动画，4 选 1 | 第 1 课 |

### 变量与列表

```
列表 我的密码 = [1, 3, 5]      // 例：团团 + 白天 + 钓鱼
变量 我的红   = 255
变量 我的绿   = 140
变量 我的蓝   = 40
变量 动画类型 = 1              // 1渐变 2闪烁 3流水 4心跳
变量 校验位   = 0              // 星航级专用
变量 k / j    = 0              // 循环计数
```

### 自定义积木【制作名片】

```
定义 制作名片 (密码列表) (红) (绿) (蓝) (动画)

// 1. 名字：依次播放 3 组灯光密码（逻辑同第 3 课）
清空屏幕
在第1行显示 "我是..."
重复 3 次 (k)
    索引 = 密码列表 第 k 项
    熄灭全部灯
    重复 (密码数量 第 索引 项) 次 (j)
        设置第 j 颗灯为 (密码颜色 第 索引 项)
    在第2行显示 密码本 第 索引 项
    等待 1 秒

// 2. 代表色：5 颗灯同时显示我的 RGB
熄灭全部灯
设置全部灯为 RGB(红, 绿, 蓝)
在第1行显示 "我的颜色"
在第2行显示 "RGB:" + 红 + "," + 绿 + "," + 蓝
等待 2 秒

// 3. 问候动画
如果 动画 = 1 那么 【渐变：亮度 10% → 100% → 10%】
如果 动画 = 2 那么 【闪烁：亮灭 3 次】
如果 动画 = 3 那么 【流水：第1→第5颗依次亮】
如果 动画 = 4 那么 【心跳：两短一长 ×2】
在第3行显示 "很高兴认识你！"

// 4. 收尾
等待 1 秒
设置全部灯为 青蓝，亮度 20%
在第1行显示 "名片：按B展示"
在第2行显示 ""
在第3行显示 ""
```

## 🎮 六、课堂流程（75 分钟）

### 1. 故事警报（5 分钟）

"数字岛名片交换会"邀请函。展示三张**示例名片**（教师提前做好的 3 台设备），让孩子按 B 看，猜分别是谁。

### 2. 无屏预测（8 分钟）· 纸面名片设计

**不碰电脑**，先在纸上设计自己的名片：

```
┌────────────────────────┐
│  我的数字名片           │
│  名字密码：__ __ __     │  ← 从密码本选 3 个词
│  代表色：R__ G__ B__    │  ← 0–255
│  问候动画：1/2/3/4      │
└────────────────────────┘
```

同桌互相**只看密码数字**，查密码本解码对方的名字。

### 3. 积木解密（12 分钟）· 自定义积木

- 引出问题："展示名片要做 4 件事，每次都要写 20 块积木，太长了。"
- 演示**自定义积木**：把 4 件事打包成一块，还能**带参数**（不同的密码、颜色、动画）
- 类比：**自定义积木 = 给点点的一道菜谱**，换材料（参数）就做出不同的菜

### 4. 程序搭建（25 分钟）

1. 在起始版里填入自己的 `我的密码` / `我的红绿蓝` / `动画类型`；
2. 补齐全 4 种动画中的**至少 2 种**；
3. 星跃级以上完成 A 键随机换色。

### 5. 实时调试（8 分钟）

实时模式下按 B 看完整名片，确认三段（名字 → 颜色 → 问候）依次播放、不串场。

### 6. 上传实战（10 分钟）· 名片交换会

上传 → 拔线。

**交换会规则**：
1. 每台设备放在桌上，屏幕朝上；
2. 同学轮流走到别人桌前，**按 B 看名片**；
3. **只看灯光**解码名字，写在《名片收集单》上；
4. 最后对照屏幕文字验证，看解码对了几张。

《名片收集单》每行：设备号 / 我解出的名字 / 实际名字 / 对了没

### 7. 复盘记录（7 分钟）

> "你的名字是怎么变成一串灯的？" → 密码本 + 颜色 + 数量。
> "同学为什么能看懂？" → 因为大家用**同一套规则**。
> "如果有人换了密码本呢？" → 解错。

填写 AI 训练日志，并向同桌说一遍"输入—处理—输出"。

## 🧪 七、测试用例

| 类型 | 输入 | 预期结果 |
|---|---|---|
| 正常 | 按 B 键 | 名字 3 组灯 → 代表色 → 问候动画，依次播放 |
| 正常 | 按 A 键（星跃+） | 随机换色，屏幕 RGB 同步更新 |

## 单元一 · 验收与交接

### 单元成果（第 4 课结束时）

- 每台点点的屏幕上都是孩子自己的数字名片，**拔线可展示**；
- 每个孩子有一份《AI 训练日志》第 1–4 页；
- 每个孩子能说出：输入 / 处理 / 输出、上传后程序住在哪里、编码需要共享规则。

### 单元大问题复盘（第 4 课末尾 5 分钟）

> **"点点怎么'感觉'到世界？它感觉到的和人一样吗？"**

引导要点：
- 点点只能收到我们**写进去的**输入（按键、摇杆、传感器）——它不会自己去看、去听；
- 点点"感觉"到的是**数字**（0/1、索引、RGB 数值），我们看到的是颜色、名字、动画；
- **不一样**：人看到的是"红色的小花"，点点手里只有 `(255, 60, 60)`。

> 教师收尾话术："这四课，我们一直在做一件事——**把我们的世界，翻译成点点能存下来的数字**。下一单元，我们要让点点自己去看、去听、去量这个世界。"

### 与单元二的衔接

| 单元一 | → | 单元二 |
|---|---|---|
| 输入来自**人**（按键、摇杆） | → | 输入来自**世界**（光线、响度、姿态） |
| 数据是**我们写死**的 | → | 数据是**实时变化**的 |
| 第 2 课：0/1 是状态 | → | 第 5 课：传感器给的是**连续数值**，要用阈值切成状态 |
