# 《团团和点点：AI行动实验室》总体方案 V5

> **面向 6–12 岁。孩子用 mBlock 积木编程，把程序上传到 CyberPi，让它在真实世界里独立运行。**
> **内容覆盖原《小云雀AI探险记》的 AI 知识体系，但不逐课对应——按"设备能做什么、孩子能理解什么"重新编排。**

---

## 版本定位：与 V4 是同一知识体系的两条产品线

| | **V4《AI编程探险记》** | **V5《AI行动实验室》** |
|---|---|---|
| 编程工具 | mBlock 积木 | mBlock 积木 |
| 运行载体 | 电脑舞台 | **CyberPi（上传后脱机运行）** |
| 硬件要求 | 无（纯软件） | 每组 1 台 CyberPi |
| 课量 | 32 | 32 |
| 核心体验 | 在屏幕上观察算法 | **拔掉线，程序还在跑** |
| 适用场景 | 无硬件教室、家庭、线上 | 创客教室、社团、营地、课后服务 |

两版**共用同一套 AI 知识地图、同一套 IP 资产、同一套三级任务卡格式**，只是"作品落在哪里"不同。已开发的内容包可互相迁移。

## 一、核心技术约束（本课程的设计地基）

### 1.1 两套运行域

这是整个课程最重要的概念，**必须在第 1 课就讲清楚**。

| | **域 A · 电脑端（mBlock 舞台）** | **域 B · 设备端（CyberPi）** |
|---|---|---|
| 位置 | 电脑上 | CyberPi 本体 |
| 输入 | 键盘、鼠标、摄像头、麦克风 | 按键、摇杆、光线、响度、姿态、WiFi/蓝牙 |
| 输出 | 角色、造型、画笔、克隆、图表 | 屏幕、5 颗 RGB 灯、扬声器 |
| 计算 | 变量、列表、运算、条件、循环 | 变量、列表、运算、条件、循环、自定义积木 |
| 智能能力 | ML 2.0 图像/姿态/音频模型、AI Service、翻译、天气、云消息 | **无**（模型推理跑不动） |
| **上传后是否生效** | **❌ 全部失效** | **✅ 全部保留，脱机可跑** |

**设计原则：每课的主作品必须在域 B 能独立运行。域 A 只用于学习、调试和可视化。**

### 1.2 实时模式 vs 上传模式（官方定义）

| | **实时模式 Live** | **上传模式 Upload** |
|---|---|---|
| 程序跑在哪 | 电脑 | CyberPi |
| 是否存储 | 不存储 | 存进 CyberPi，直到被覆盖 |
| 连接要求 | 必须保持连接、mBlock 必须开着 | **可拔线、可关软件** |
| 可用事件 | 绿旗、键盘、角色事件 | **仅 `当CyberPi启动` / `当CyberPi按键被按下` 等设备事件** |
| 用途 | 学习新积木、看数据、调试 | 作品验收、真实场景测试 |

**⚠️ 三条硬约束（官方明确，会直接决定孩子能不能跑通）：**

1. **上传模式下，绿旗事件和键盘事件不可用。** 孩子 Scratch 学来的习惯在这里会失效——必须用 `当 CyberPi 启动时` 和 `当 CyberPi [A/B/摇杆] 被按下`。这是本课程第一周的常见踩坑点。
2. **一次只能连接一台设备。** 分组教学时，各组必须轮流连接上传，或用"一机一电脑"配置。
3. **上传会覆盖旧程序。** 每次上传前提醒孩子：上一课的作品会被替换，重要作品要先保存 `.mblock` 文件。

**✅ 一条好消息**：`Display+` 扩展的 **Doodle 涂鸦**（turtle 绘图）**只能在上传模式使用**，可以直接在 CyberPi 屏幕上画像素图、轨迹图——这是"像素"和"梯度下降轨迹"两课的天然载体。

### 1.3 上传后还能不能用？速查

| 能力 | 上传后 | 说明 |
|---|:---:|---|
| 按键 / 摇杆输入 | ✅ | 设备事件 |
| 光线 / 响度 / 姿态传感器 | ✅ | 设备端读取 |
| 屏幕显示文字图形 | ✅ | 需 `当CyberPi启动` 事件，否则屏幕空白 |
| Display+ Doodle 画图 | ✅ | **仅上传模式** |
| 5 颗 RGB 灯、扬声器 | ✅ | |
| 变量 / 列表 / 条件 / 循环 / 自定义积木 | ✅ | |
| WiFi / 蓝牙通信 | ✅ | |
| 电机 / 舵机 / 灯带 | ⚠️ | 需 Pocket Shield，列为选配 |
| 舞台角色、造型、画笔、克隆 | ❌ | 域 A |
| 摄像头相关（视频侦测、ML 图像/姿态） | ❌ | 需电脑在场 |
| ML 2.0 音频模型 | ❌ | 需电脑在场 |
| 联网服务（AI Service、翻译、天气、云消息） | ❌ | 需电脑在场 |
| 绿旗、键盘事件 | ❌ | 上传模式不支持 |

**结论：32 课中只有第 17、20 两课需要电脑在场做模型推理。** 这两课采用"电脑训练/识别 → 结果发给设备 → 设备做反馈"的 split 架构，并且都配无摄像头等价方案。

### 1.4 CyberPi 硬件能力边界（沿用 V1 校正结论）

**可可靠使用**：彩色屏幕、5 颗 RGB LED、按键与五向摇杆、光线传感器、响度采样、姿态/陀螺仪、扬声器、WiFi/蓝牙。

**不可使用 / 勿写入教案**：
- 板载**没有摄像头**，不能做"识别贴纸、识别卡片、识别水果"；
- 板载**不是 5×5 LED 点阵**（是 5 颗 RGB 灯）；
- 光线传感器只能判断明暗，**不能知道遮挡它的是哪张卡**；
- 电机、舵机、LED 灯带需 Pocket Shield，**不是本体功能**；
- 语音识别、生成式 AI 属联网扩展，**必须配不联网等价玩法**。

## 二、课程结构总览

### 课程名

**《团团和点点：AI行动实验室》**
副标题：**32 次任务，把程序上传给点点，在真实世界里检验 AI**

### 编排逻辑

不追随原课顺序，而是按**"设备能力递进 × AI 认知递进"**双轴重排：

```
唤醒点点  →  教点点感知  →  教点点思考  →  教点点分类
（信息进出）  （数据从哪来）  （规则与算法）  （规则到学习）
      ↓
教点点学习  →  看穿模型  →  一起创作和判断  →  带点点出门
（样本到模型） （内部发生什么） （生成与核查）  （责任与协作）
```

### 单元结构：8 单元 × 4 课 = 32 课

**每单元 = 3 节内容课 + 1 节项目课。** 项目课不是复习课，是本单元的"脱机部署验收"——把前三课的能力组合起来，放到真实场景里跑。

| 单元 | 名称 | 课次 | 主题 | 单元大问题 |
|---:|---|---:|---|---|
| 一 | 唤醒点点 | 1–4 | 信息如何进出机器 | 点点怎么"感觉"到世界？它感觉到的和人一样吗？ |
| 二 | 教点点感知 | 5–8 | 数据从哪里来 | 传感器给的是"事实"还是"读数"？ |
| 三 | 教点点思考 | 9–12 | 规则与算法 | 机器为什么会严格照做，却不一定做对？ |
| 四 | 教点点分类 | 13–16 | 规则、特征与预测 | 分类和猜测的差别在哪里？ |
| 五 | 教点点学习 | 17–20 | 从样本到模型 | 点点答对了，是真学会还是刚好见过？ |
| 六 | 看穿模型 | 21–24 | 内部发生了什么 | 模型脑子里到底在算什么？ |
| 七 | 一起创作和判断 | 25–28 | 生成与核查 | 流畅的话，等于正确的话吗？ |
| 八 | 带点点出门 | 29–32 | 责任与协作 | 一个"很聪明"的点点，怎样才算可信、负责？ |

### 建议课制

- 32 课，每课 60–75 分钟，一学年（两学期各 16 课）；
- 2 人一组，每组 1 台 CyberPi；一人当"数据侦探"（观察、记录），一人当"程序工程师"（搭建、上传），**中途换岗**；
- 编程全程 mBlock 积木；11–12 岁可在上传模式查看 Python 对照，但**不把语法记忆当目标**；
- Pocket Shield、mBuild 传感器、电机单列为选配，不影响主课程闭环。

## 三、年龄分层：一课三阶，不拆成三套课

| 层级 | 建议年龄 | 在 mBlock 里做什么 | 教师提供什么 | 课堂成果 |
|---|---:|---|---|---|
| **星芽级** | 6–8 岁 | 排序、补空、替换参数，识别并修改 5–10 块核心积木 | 半成品程序、图标化步骤卡 | 能说出"输入—规则—输出" |
| **星跃级** | 9–10 岁 | 根据流程图独立搭建 10–25 块积木，记录数据 | 目标效果、必要积木清单 | 能用证据解释程序为何这样运行 |
| **星航级** | 11–12 岁 | 自主设计变量、阈值、测试方案与改进策略 | 开放任务、评价标准 | 能评价模型局限并提出迭代方案 |

分层只改变挑战卡，不改变硬件包、故事和课堂主任务，以控制制作与培训成本。

## 四、每课统一课堂结构

| 环节 | 时间 | 场域 | 关键动作 |
|---|---:|---|---|
| 1. 故事警报 | 5 分钟 | 动画/设备屏幕 | 团团和点点遇到新问题，提出本课大问题 |
| 2. 无屏预测 | 5–10 分钟 | 纸卡/身体 | 不碰电脑，先猜结果，收集不同猜想 |
| 3. 积木解密 | 10 分钟 | mBlock | 学本课 1–2 个新结构，**明确它属于域 A 还是域 B** |
| 4. 程序搭建 | 15–20 分钟 | mBlock | 排序、补全或独立搭建 |
| 5. 实时调试 | 10 分钟 | 电脑 + 设备（实时模式） | 看传感器数据、定位错误 |
| 6. **上传实战** | **10 分钟** | **设备（上传模式）** | **拔线，在真实场景测试——本课定义性动作** |
| 7. 复盘记录 | 5 分钟 | AI 训练日志 | 记录输入、规则、输出、证据与改进 |

**每课验收两个目标，缺一不可：**

1. **编程目标**：今天新增了哪种程序结构或数据处理方法？
2. **AI目标**：这段程序说明了 AI 的什么原理或局限？

**每课结束状态**：程序已上传，设备可以拔线带走。

## 单元一 · 唤醒点点（第 1–4 课）

### 第 1 课 · 点点醒了

- 🎯 **编程目标**：mBlock 界面（设备区/积木区/脚本区）、设备事件、顺序执行、**上传按钮与两种模式**
- 🧠 **AI目标**：输入 → 处理 → 输出；程序上传后离开电脑也能工作
- 📱 **CyberPi 任务**：`当CyberPi启动` 显示点点的脸 → 按 B 键 → 屏幕问候 + 5 颗灯亮起 + 播放声音
- ⬆️ **上传后**：拔线、关掉 mBlock，按 B 键仍然响应。**这是全课程最重要的一次体验**
- 🔗 **原课**：1（信息）、31（人机协作）
- ⭐ **分层** 芽：补 1 个输出积木 / 跃：独立完成三种输出并成功上传 / 航：改成"摇杆四方向四种反应"，并验证拔线后是否仍生效
- ⚠️ **教师重点**：本课必须亲手演示"绿旗在上传模式失效"，让孩子从第一节课就建立两套运行域的概念

### 第 2 课 · 开关城的两兄弟

- 🎯 **编程目标**：变量、状态切换、`如果/否则`、列表
- 🧠 **AI目标**：0 和 1 是两种状态；多个状态组合能表示更多信息
- 📱 **CyberPi 任务**：A 键=1、B 键=0，5 颗灯对应 5 位二进制，屏幕实时显示当前值与对应图案
- ⬆️ **上传后**：脱机用 A/B 键切换，屏幕实时换算
- 🔗 **原课**：2（0和1）
- ⭐ **分层** 芽：补 2 个状态判断 / 跃：完成 5 位输入与换算 / 航：扩展到 8 位，说明能表示多少种信息

### 第 3 课 · 五色密码通信

- 🎯 **编程目标**：列表、索引、循环、字符串连接
- 🧠 **AI目标**：编码与解码必须用同一套规则；规则错了，信息就丢了
- 📱 **CyberPi 任务**：摇杆选符号 → 编码成 5 色灯光序列 → 同伴用另一台设备（或纸面密码表）解码
- ⬆️ **上传后**：两台脱机设备互发密码；或一台编码、同伴纸面解码
- 🔗 **原课**：3（编码）、6（RGB）
- ⭐ **分层** 芽：用现成密码表补解码 / 跃：自建密码表互发互解 / 航：故意错开一位，分析为什么全部解错

### 第 4 课 ·【项目】点点数字名片

- 🎯 **编程目标**：自定义积木、组合逻辑、屏幕显示
- 🧠 **AI目标**：综合——信息表示、编码、存储
- 📱 **CyberPi 任务**：用编码记录昵称 / 代表色 / 问候动作，脱机展示给同学
- ⬆️ **上传后**：全程脱机运行，作为单元成果互相传阅
- 🔗 **原课**：1、2、3、6
- ⭐ **分层** 芽：在半成品上改昵称和代表色 / 跃：独立设计名片并加入问候动作 / 航：加入"校验位"，让接收方能发现传错

**单元成果**：每台点点的屏幕上是孩子自己的数字名片，拔线也能展示。

## 单元二 · 教点点感知（第 5–8 课）

### 第 5 课 · 黑暗森林侦察站

- 🎯 **编程目标**：读取传感器值、变量、`如果/否则`、阈值
- 🧠 **AI目标**：传感器把世界变成数值；阈值是把连续世界切成判断的开关
- 📱 **CyberPi 任务**：连续读光线 → 屏幕显示数值 → 暗到阈值以下自动亮灯（智能夜灯）
- ⬆️ **上传后**：带着设备去暗处、亮处、窗帘边实测，记录实际触发阈值
- 🔗 **原课**：1（信息）、8（噪声）、9（条件判断）
- ⭐ **分层** 芽：补阈值判断 / 跃：完成夜灯并在三种环境测试 / 航：找出"黄昏/阴天"这类边界情况，讨论单一阈值的脆弱

### 第 6 课 · 声音怪兽现形

- 🎯 **编程目标**：循环采样、平均值、列表
- 🧠 **AI目标**：单次采样有噪声；多次平均能稳定，但会变慢、会抹掉突发
- 📱 **CyberPi 任务**：读响度 → 安静/正常/过响三级提示，5 颗灯分级点亮
- ⬆️ **上传后**：在嘈杂教室对比"读 1 次"与"读 10 次取平均"的稳定性
- 🔗 **原课**：8（噪声）
- ⭐ **分层** 芽：观察数值跳动 / 跃：实现平均降噪并对比 / 航：找出平均"抹掉突发响声"的案例，讨论什么时候不该平均

### 第 7 课 · 摇一摇方向罗盘

- 🎯 **编程目标**：姿态/陀螺仪值、方向判断、校准变量
- 🧠 **AI目标**：姿态也是信息；"水平"不是绝对的，需要先定义（校准）
- 📱 **CyberPi 任务**：倾斜控制屏幕上的小球走迷宫，先校准水平
- ⬆️ **上传后**：脱机倾斜玩迷宫；换一个同学拿设备，看是否需要重新校准
- 🔗 **原课**：1（信息）、14（特征）
- ⭐ **分层** 芽：补 2 个方向判断 / 跃：完成四方向迷宫 / 航：测试"换手持角度"导致失灵，实现开机校准

### 第 8 课 ·【项目】教室环境守护器

- 🎯 **编程目标**：多条件 `与/或`、综合判断、实地部署
- 🧠 **AI目标**：单一传感器会误判，多条线索更可靠
- 📱 **CyberPi 任务**：综合光线 + 响度 + 按键 → 判断"该不该提醒"，屏幕给建议、灯光分级
- ⬆️ **上传后**：部署到教室真实运行一节课，记录误报与漏报次数
- 🔗 **原课**：1、8、9
- ⭐ **分层** 芽：补 1 个条件 / 跃：完成双条件并实地测试 / 航：统计误报与漏报，调整规则并给出数据

**单元成果**：教室环境守护器实地挂机运行一节课，孩子带回一张误报记录表。

## 单元三 · 教点点思考（第 9–12 课）

### 第 9 课 · 红灯停绿灯行

- 🎯 **编程目标**：嵌套 `如果/否则`、`与/或/非`、计时器
- 🧠 **AI目标**：自动决策来自明确条件；规则冲突会带来风险
- 📱 **CyberPi 任务**：按键 = 行人请求，光线 = 昼夜，5 颗灯充当红绿灯，屏幕倒计时
- ⬆️ **上传后**：脱机完整运行，测试"车和行人同时请求"时怎么办
- 🔗 **原课**：9（条件判断）
- ⭐ **分层** 芽：补 2 个分支 / 跃：完成并处理冲突 / 航：加"急救车优先"例外，验证是否真的解决冲突

### 第 10 课 · 会数数的行动教练

- 🎯 **编程目标**：`重复次数`、`重复执行直到`、计数变量
- 🧠 **AI目标**：循环让重复任务自动化；"做到为止"必须有明确停止条件
- 📱 **CyberPi 任务**：姿态变化计数（摇一摇记一次），达到目标后停止并庆祝
- ⬆️ **上传后**：脱机计数；测试快速摇动是否漏计
- 🔗 **原课**：10（循环）
- ⭐ **分层** 芽：补次数参数 / 跃：完成两种循环并比较 / 航：找出漏计/重复计数的原因并修复

### 第 11 课 · 披萨流水线

- 🎯 **编程目标**：广播、多段脚本、`等待`、计时器
- 🧠 **AI目标**：大任务可以分解；并行能提速，但增加协调成本
- 📱 **CyberPi 任务**：屏幕显示接单→备料→烘烤→送餐四道工序，按键下单，计时器计时
- ⬆️ **上传后**：脱机接单；比较串行与并行的总耗时
- 🔗 **原课**：11（任务分解）
- ⭐ **分层** 芽：补 2 条广播 / 跃：完成四工序并测量耗时 / 航：找出瓶颈工序并重新分配，用数据证明更快

### 第 12 课 ·【项目】Bug虫大搜查

- 🎯 **编程目标**：读程序、拆分测试、定位、修改、复测
- 🧠 **AI目标**：调试 = 定位原因 → 修改 → 再验证；**把大程序拆小是核心手段**（本课同时覆盖"任务分解"）
- 📱 **CyberPi 任务**：教师给一个"有 3 个 Bug 的智能值日提醒器"，孩子逐个修复
- ⬆️ **上传后**：上传前后跑同一组测试用例，对比修复效果
- 🔗 **原课**：11（任务分解）、12（调试）
- ⭐ **分层** 芽：找出 1 个明显 Bug / 跃：修复全部 3 个并填写调试记录 / 航：自己埋一个能骗过测试的隐藏 Bug 考同学

**单元成果**：一个修复完毕、脱机可用的智能值日提醒器 + 一份调试记录。

### 第 13 课 · 袜子分类工厂

- 🧠 **AI目标**：分类结果取决于规则；规则没覆盖的情况会暴露漏洞

### 第 14 课 · 特征放大镜

- 🔗 **原课**：14（特征）

### 第 15 课 · 猜一猜明天带伞吗

- 🎯 **编程目标**：列表、计数、百分比
- 🧠 **AI目标**：预测依据过去数据，输出的是**可能性**不是确定答案；样本量影响可信度
- 📱 **CyberPi 任务**：输入历史天气（或孩子记录的光线/是否下雨）→ 算"多云后下雨"的比例 → 屏幕显示带伞概率
- ⬆️ **上传后**：脱机查询；测试只有 3 条数据时概率有多不可信
- 🔗 **原课**：15（预测）
- ⭐ **分层** 芽：补统计积木 / 跃：完成两个条件的概率对比 / 航：说明样本量对可信度的影响

### 第 16 课 ·【项目】教室天气预测站

- 🎯 **编程目标**：列表、综合判断、屏幕图表（Display+ 绘制柱状）
- 🧠 **AI目标**：综合——数据收集 → 统计 → 预测 → 表达不确定性
- 📱 **CyberPi 任务**：一周实地记录光线/是否下雨，设备给出明日带伞建议与概率
- ⬆️ **上传后**：部署在教室窗台，每天按键记录一次，连续运行一周
- 🔗 **原课**：15（预测）
- ⭐ **分层** 芽：完成每日记录 / 跃：完成统计与建议输出 / 航：评估自己模型的准确率，并说明它什么时候不灵

**单元成果**：一台在教室窗台连续运行一周的预测站 + 一张真实准确率统计。

## 单元五 · 教点点学习（第 17–20 课）

- 🧠 **AI目标**：监督学习依赖带正确标签的样本；错标签和样本不均衡会毁掉模型
- 📱 **CyberPi 任务**：用设备采集"安静/吵闹"样本（按键打标签），屏幕显示每类样本数

- ⭐ **分层** 芽：采集并打 10 条标签 / 跃：发现并修正错标签、补齐不均衡类别 / 航：设计"故意混入错标签"实验，观察模型变化

### 第 18 课 · 新题考试日

- 🎯 **编程目标**：列表、随机抽取、准确率计算、分组
- 🧠 **AI目标**：测试必须用没见过的数据；旧题高分不等于学会

- ⬆️ **上传后**：脱机考试；旧题、新题各测一轮
- 🔗 **原课**：16（过拟合）、17（训练集/测试集）
- ⭐ **分层** 芽：完成一轮测试 / 跃：完成新旧题对比并记录 / 航：构造"背答案反而更高分"的场景并解释

### 第 19 课 · 小狗自己找骨头

- 🎯 **编程目标**：随机数、奖励变量、循环、列表记录
- 🧠 **AI目标**：行为可通过"尝试—反馈—调整"逐步改进；**奖励怎么设计，决定学到什么**
- 📱 **CyberPi 任务**：屏幕上的小狗随机探索迷宫，靠近目标加分、撞墙扣分；摇杆控制轮次
- ⬆️ **上传后**：脱机跑 100 轮，屏幕显示累计奖励曲线
- 🔗 **原课**：18（强化学习）
- ⭐ **分层** 芽：观察分数变化 / 跃：完成奖励规则并跑 100 轮 / 航：改奖励规则（改为奖励"少走步数"），看学到的策略如何变化

### 第 20 课 ·【项目】会学习的分类助手

- 🎯 **编程目标**：ML 2.0 采样—训练—测试（电脑端）+ 设备反馈（设备端）的 split 架构
- 🧠 **AI目标**：监督学习全流程；置信度不是准确率；模型会受环境影响
- 📱 **CyberPi 任务**：电脑端用 ML 2.0 训练手势/声音模型 → 识别结果发给设备 → 屏幕显示类别，5 颗灯按置信度分级
- ⬆️ **上传后**：**能独立跑的只有"接收结果 → 显示/灯光"这一段**；识别本身需要电脑在场（实时模式）
- 📴 **无摄像头 / 无网等价**：改用"手填特征值 + 最近邻规则"分类器，全程在设备端运行，脱机可用
- 🔗 **原课**：19（监督学习）
- ⭐ **分层** 芽：补 3 个"如果识别结果是……"分支 / 跃：自建类别、采集样本、用未参与训练的同学测试 / 航：控制变量测试（换背景、距离、光线），加入"置信度不足时拒识"，写出三个不适用场景
- ⚠️ **实施注意**：ML 2.0 每个任务只能建 1 个模型（新建会覆盖），需课前统一命名、课末导出；**避免采集儿童面部等身份性数据**，推荐手势、积木、文具等非身份目标

**单元成果**：一个能识别并给出置信度的分类助手 + 一份"它在什么情况下会失败"的清单。

## 单元六 · 看穿模型（第 21–24 课）

### 第 21 课 · 点亮聪明灯

- 🎯 **编程目标**：变量、加权求和、比较、阈值
- 🧠 **AI目标**：单个神经元把输入合并后做一个简单决定
- 📱 **CyberPi 任务**：三个输入（按键次数/光线/响度）× 权重求和，超过阈值点亮全部 5 颗灯；屏幕显示加权和与阈值
- ⬆️ **上传后**：脱机运行，实时看到中间计算过程
- 🔗 **原课**：21（神经元）
- ⭐ **分层** 芽：补阈值判断 / 跃：完成 3 输入神经元 / 航：找出"怎么调阈值都分不开"的输入，说明单个神经元的局限

### 第 22 课 · 音量旋钮决定谁更重要

- 🎯 **编程目标**：变量、乘法、摇杆调参、列表
- 🧠 **AI目标**：权重决定模型重视什么；权重不同，同一份输入会得到不同结论
- 📱 **CyberPi 任务**：摇杆调节三个权重，屏幕实时显示总分与排名变化，可保存两组权重对比
- ⬆️ **上传后**：脱机调参
- 🔗 **原课**：23（权重）
- ⭐ **分层** 芽：调一个权重观察 / 跃：完成三权重评分 / 航：找出明显不合理的权重组合，讨论"权重该由谁决定"

### 第 23 课 · 从边边角角到整张脸

- 🎯 **编程目标**：广播、自定义积木、分层脚本
- 🧠 **AI目标**：分层处理把复杂识别拆成较简单的步骤
- 📱 **CyberPi 任务**：三层——第一层判边缘（光线突变）、第二层组合局部、第三层下结论；屏幕分三步显示
- ⬆️ **上传后**：脱机按键推进每一层
- 🔗 **原课**：22（分层）
- ⭐ **分层** 芽：补 1 层的广播 / 跃：连通三层 / 航：去掉中间层看是否还能识别，讨论"深度"带来什么

### 第 24 课 ·【项目】慢慢调准的小箭头

- 🎯 **编程目标**：变量、循环、斜率模拟、**Display+ Doodle 绘制轨迹**
- 🧠 **AI目标**：模型通过多次小调整减少错误；步长太大会震荡，太小会很慢
- 📱 **CyberPi 任务**：用陀螺仪倾斜当"坡度"，屏幕上的小球一步步走向最低点，Doodle 画出轨迹，记录步数
- ⬆️ **上传后**：脱机倾斜设备驱动小球下山；比较不同步长的步数
- 🔗 **原课**：24（梯度下降）
- ⭐ **分层** 芽：调步长观察 / 跃：记录不同步长的步数 / 航：实现"接近目标时自动减小步长"，用数据证明更快
- 💡 **技术提示**：Doodle 涂鸦**仅上传模式可用**，本课天然适合全程用上传模式教学

**单元成果**：一块画着下山轨迹的屏幕 + 一张"步长 vs 步数"对照记录。

- 🧠 **AI目标**：语言模型是按上下文预测下一个词，不是在回忆唯一答案
- 📱 **CyberPi 任务**：预置词频表，屏幕显示三个候选词及概率条，按键选择并连成句子

- 📱 **CyberPi 任务**：预置故事库（事实/推测/虚构三类），A/B 键逐句打标，5 颗灯显示无来源比例
- ⬆️ **上传后**：脱机核查，全程离线

- ⭐ **分层** 芽：给 3 句话打标 / 跃：完成整篇核查并出报告 / 航：找出"听起来最可信但没来源"的句子，说明它为什么最危险

### 第 28 课 ·【项目】负责任的创作机

- 🎯 **编程目标**：综合——参数化生成 + 随机种子 + 标记输出

- 🔗 **原课**：25、27、28
- ⭐ **分层** 芽：完成生成模块 / 跃：完成生成 + 标记 / 航：写出作品的免责说明与局限清单

**单元成果**：一台会"自我标注"的创作机 + 一份使用须知。

## 单元八 · 带点点出门（第 29–32 课）

### 第 29 课 · 隐私守门员

- 🎯 **编程目标**：列表、条件、关键词判断

- ⭐ **分层** 芽：给 3 个任务做判断 / 跃：完成规则并处理边界（昵称算不算隐私）/ 航：讨论"匿名化后还能不能被重新识别"，以及删除数据的困难

### 第 30 课 · 公平比赛委员会

- 🎯 **编程目标**：列表、循环、分组统计、差异阈值
- 🧠 **AI目标**：AI 会继承数据或规则中的偏见；公平需要主动测试
- 📱 **CyberPi 任务**：对同一批数据跑两套评分规则，屏幕显示两组通过率，差异超阈值亮红灯

### 第 31 课 · 超级搭档

- 🎯 **编程目标**：广播、计时器、多段协作、条件
- 🧠 **AI目标**：人与机器优势不同；**最终责任不能交给程序**
- 📱 **CyberPi 任务**：设备快速搜索/计算给出候选，人按 A/B 做最终决定；计时器比较全人工 / 全机器 / 人机分工三种方案
- ⬆️ **上传后**：脱机完成三种方案的计时对比
- 🔗 **原课**：31（人机协作）
- ⭐ **分层** 芽：完成一次分工 / 跃：测三种方案并记录 / 航：设计"机器给错建议、人必须否决"的场景，讨论出错时责任在谁

### 第 32 课 ·【毕业项目】数字岛救援行动

- 🎯 **编程目标**：自主选用事件、条件、循环、变量、列表、广播、自定义积木
- 🧠 **AI目标**：AI 作品要同时考虑功能、可靠性、公平、隐私与人的责任
- 📱 **CyberPi 任务**：自选一个真实问题，至少两种输入 + 两种反馈，上传后脱机接受同伴测试
- ⬆️ **上传后**：全程脱机运行，公开展示
- 🔗 **原课**：31、32 及全课程
- ⭐ **分层** 芽：完成一个功能模块 / 跃：独立完成作品并测试 / 航：完成作品 + 局限说明 + 伦理自检

**毕业项目必交材料**：

1. 一份问题说明（要解决什么、给谁用）；
2. 一张"输入—处理—输出"流程图，**标明哪些跑在设备上、哪些需要电脑**；
3. 一个已上传到 CyberPi 的可脱机运行作品 + 源 `.mblock` 文件；
4. 至少三条测试记录，其中一条必须是失败或边界情况；
5. 一项根据测试完成的修改（改前/改后对比）；
6. 一张隐私、公平和可靠性自检表。

## 六、三级任务卡写法

每课任务卡按同一格式，只改变开放度：

| 区块 | 星芽级（6–8） | 星跃级（9–10） | 星航级（11–12） |
|---|---|---|---|
| 给了什么 | 半成品程序 + 图标化步骤卡 | 目标效果 + 必要积木清单 | 开放任务 + 评价标准 |
| 要做什么 | 排序、补空、替换参数 | 按流程图独立搭建 | 自主设计变量、阈值与测试方案 |
| 上传要求 | 成功上传并演示一次 | 上传后完成一项真实场景测试 | 上传后完成三类测试并记录数据 |
| 要说出什么 | 输入是什么、结果是什么 | 输入—处理—输出各是什么 | 局限在哪、还能怎么改 |

### 示例：第 20 课《会学习的分类助手》

**星芽级**：教师提供已建好三个类别的模型页面 → 孩子采集样本并训练 → 在半成品程序中补入三个"如果识别结果是……"分支 → 换一个背景测试一次。

**星跃级**：自己建立类别、采集训练样本、完成识别程序 → 显示三个类别的置信度 → 用未参与训练的同学测试并记录准确率。

**星航级**：自行设计训练集与测试集（程序禁止同一条数据同时出现）→ 控制变量比较样本数量、背景或角度的影响 → 加入"最高置信度不足时拒识"规则 → 写出三个模型不适用的场景。

## 七、课程评价

不以"程序一次上传成功"作为最高评价。

| 维度 | 评价问题 | 权重 |
|---|---|---:|
| 程序理解 | 能否预测和解释关键积木的作用？ | 20% |
| 程序实现 | 能否完成有效的输入、处理和输出？ | 25% |
| 测试证据 | 脱机后是否测试了正常、边界和意外情况？ | 25% |
| 迭代改进 | 是否根据证据修改程序或数据？ | 20% |
| AI 责任 | 是否考虑可靠性、隐私、公平和人的责任？ | 10% |

### AI 训练日志（每课一页）

1. 今天的任务是什么？
2. 我预测的结果 vs 拔线后实际的结果（哪里不一样？）
3. 我的程序：输入 → 处理 → 输出 分别是什么？**哪些跑在点点上？**
4. 我测了哪三种情况？哪个失败了？
5. 我根据测试改了什么？改完变好了吗？
6. 这段程序说明了 AI 的什么道理 / 什么局限？

## 八、硬件物料与常见故障

### 标准包（完成 32 课）

- CyberPi × 1 / 组
- USB-C 数据线 × 1 / 组
- 可露出屏幕、麦克风、光线传感器、摇杆、A/B 键、Home 键和接口的**点点云朵保护套/桌面底座**
- 电脑或平板 × 1 / 组，安装 mBlock 5（Web 版需配 mLink）
- 任务卡、特征卡、数据卡、测试卡、可擦写记录板
- 备用电池或充电宝（脱机部署课需要）

### 选配包（仅拓展用）

- Pocket Shield + 电池（移动部署、电机/舵机）
- mBuild 传感器（距离、温湿度、土壤湿度等）
- LED 灯带、舵机、直流电机

**选配硬件是"作品能力扩展"，不能成为理解核心 AI 概念的前置条件。**

### 常见故障速查

| 症状 | 原因 | 处理 |
|---|---|---|
| 上传后屏幕空白 | 缺少 `当CyberPi启动` 事件，或未向屏幕输出内容 | 检查事件积木；启动时先打印一句提示 |
| 上传后程序没反应 | 用了绿旗或键盘事件 | 改为 `当CyberPi启动` / `当CyberPi按键被按下` |
| 上传失败 / 找不到端口 | 数据线、USB 口、驱动或 mLink 问题 | 换线换口；Web 版确认 mLink 已启动 |
| 连不上第二台设备 | 一次只能连接一台 | 分组轮流上传，或一机一电脑 |
| 上一课作品不见了 | 新程序覆盖旧程序 | 每课前先保存 `.mblock` 到作品集 |
| 传感器读数跳得厉害 | 单次采样噪声 | 引导进入第 6 课的"多次平均" |
| 两台设备互发失败 | WiFi/蓝牙通信配置 | 退回到"一台编码、同伴纸面解码" |
| 设备移动时断电 | 电池不足 | Pocket Shield 或充电宝 |

## 十一、开发底线

1. **每课必须以"上传并拔线运行"收尾。** 不能上传的作品不写入本课程。
2. **明确两套运行域。** 每课任务卡要标注哪些积木上传后失效，避免孩子在域 A 做了很多、拔线后什么都没有。
3. **不把"用了传感器"直接称作 AI。** 必须指出感知、规则、学习或决策发生在哪里。
4. **不伪装硬件能力。** 不做"识别卡片""识别水果"等本体无法完成的任务；涉及摄像头的一律走电脑端，并写明。
5. **不承诺"100% 准确""完全理解""提示清楚就一定对"。**
6. **每课至少有一个失败或边界测试。** 让孩子知道"能上传"不等于"解决了问题"。
7. **不把错误归咎于孩子。** 错误是收集证据和改进系统的入口。
8. **不采集儿童姓名、声音、面部照片等身份性数据。** 第 20 课推荐手势、积木、文具等非身份目标。
9. **模拟机器学习时必须说清**：哪些步骤是孩子定的规则，哪些是程序根据数据更新的参数。**禁止把写死的 if-else 包装成"程序自己学会了"。**
10. **选配硬件不进入必修。** Pocket Shield、mBuild 只作拓展，不影响主课程闭环。

## 十二、样板课开发顺序

先做四课，验证四个不同风险点：

| 顺序 | 课程 | 验证什么 |
|---:|---|---|
| 1 | **第 1 课《点点醒了》** | 6–8 岁能否理解两种模式、设备事件与上传流程（最大风险点） |
| 2 | **第 6 课《声音怪兽现形》** | 真实传感器数据 + 噪声 + 脱机部署是否成立 |
| 3 | **第 20 课《会学习的分类助手》** | ML 2.0 split 架构 + 无摄像头等价方案是否都跑得通 |
| 4 | **第 30 课《公平比赛委员会》** | AI 伦理能否通过设备实验呈现，而不是说教 |

四课通过后，再锁定课件模板、任务卡版式、积木数量上限、素材规格与教师培训内容。
